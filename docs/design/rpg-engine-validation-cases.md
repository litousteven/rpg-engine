## Case 1：Boss 掉落骨头

**场景**：玩家击杀特殊 boss「蚀骨巨蟒」，掉落一根骨头。要求：① 入背包，具备个数/稀有度/价格；② 特殊 boss 的骨头描述带特殊来源说明；③ 衍生用途——拍卖定价、制药属性是否与 boss 特质一致、制武器；④ 作为剧情道具交给 NPC 时触发特殊剧情或满足任务要求。

### 推演

**T0 掉落入库（步骤 5→6）**：终结 intent 结算 → boss HP≤0 → 死亡事件 → 掉落表掷骰（种子 RNG，进事件日志）。掉落表与账本条目：

```json
// 规则库：掉落表
{ "encounterId": "boss.bone_maw",
  "loot": [ { "template": "item.bone.large", "chance": 1.0,
              "named": true, "essence": ["poison_affinity", "colossal"] } ] }

// 账本：具名掉落升级为唯一实例（带 uid，不与普通骨头堆叠）
{ "uid": "item.inst.000317", "template": "item.bone.large", "qty": 1,
  "rarity": "rare", "basePrice": 120,
  "essence": ["poison_affinity", "colossal"],
  "provenance": { "source": "boss.bone_maw", "turn": 42, "dropRoll": "seed:a91f" } }
```

个数/稀有度/价格全为引擎字段；`essence` 标签从 boss 特质继承到材料，是后续特质一致性的锚点。LLM 不参与。

**T1 特殊来源描述（步骤 7）**：P2 的镜像——描述从结构化事实渲染，不从描述抽取事实。

```text
描述投影 = [基础] 一根粗大的兽骨，断面密布蜂窝状孔洞。
           [来源] 取自「蚀骨巨蟒」· 第 42 回合 · 具名掉落。
           [风味] （可选缓存）Narrator/ContentGen 按上述事实润色
```

来源不可能说谎：渲染自 provenance 字段，provenance 由引擎写入。拔掉 LLM 保留模板文案 + 来源行。

**T2 拍卖定价**：纯函数，输入全为结构化字段（P1）：

```text
成交价上限 = f(basePrice, rarity系数, essence溢价, 市场状态, 商人画像)
          = 120 × rare(1.8) × essence(+0.7) × 市场紧缩(0.9) ≈ 376
```

拍卖为交互模式（出价/抬价/观望/离场菜单，引擎结算）。L2 商人可讨价还价，但报价上限引擎计算，只能在区间内决策。LLM 只渲染演出、决定是否跟价，不碰数字。

**T3 制药/制武器（特质一致性）**：配方是「essence → 效果原语」映射表（规则库数据）。制药 `craft.medicine.bone_broth` 把 `poison_affinity` 映到 `poison_resist`、`colossal` 映到 `max_hp_up`；制武器 `craft.weapon.bone_blade` 把同一标签分别映到 `poison_on_hit`、`heavy`。**一致性由构造保证**：特质标签走 boss → 骨头 → 成品的继承链，路径上没有 LLM 插手的位置。产出为自定义实体（设计稿 §5.1），provenance 携带完整血统链（lineage: boss → bone → product），供触发器日后查询。制作动作入口为场景可供性（炼金台/铁匠铺标签，§4.3）；增富层只能提议措辞，不能发明菜单外动作。

**T4 剧情道具交给 NPC**：四层叠加——① 触发器：任务阶段条件表达式 `item_delivered(npc: "elder_yun", tag: "bone_of_bone_maw")`，「给予物品」是对话态基础菜单动作，账本转移 → 触发器级联 → 任务阶段机前进（提交才算数）；② 作者内容：该阶段挂载的剧情载荷（对话分支/场景切换/遭遇生成）为内容期数据，触发即执行；③ Director：看到事件后可发舞台指令（`act_awed`、`converge`，TTL 2 回合），但不能无中生有造新任务——任务阶段提议必须落在作者任务图内并走校验；④ NPC 反应：L0 长老收效用偏置，台词由前台体验 Agent 代笔，代笔输入含任务上下文，演出与事实同源。

### 验证矩阵

| 要求 | 机制 | 拔掉 LLM |
|---|---|---|
| 入背包/个数/稀有度/价格 | 掉落表 + 账本 + 种子 RNG | 完整工作 |
| 特殊来源描述 | provenance + 描述投影（事实→文案） | 模板保留来源行 |
| 拍卖定价 | 定价纯函数（规则库） | 完整工作 |
| 制药/制武器属性=特质 | essence 继承 + 配方映射 | 完整工作 |
| 剧情触发 | 条件触发器 + 任务阶段机 + 作者载荷 | 剧情事实照常触发 |
| 特殊剧情演出 | Director 舞台指令 + 代笔 | 演出消失，触发不受影响 |

### 暴露缺口

G1（实例身份 → 已收编 §5.1）、G2（定价子系统 → §8.1）、G3（材料/配方/essence 继承 → §5.3）、G4（描述投影 → §5.4）、G5（条件语言物品谓词 → §7）、G6（交易/拍卖交互模式 → §4.5）。

## Case 2：玩家捡到遗迹物品

**场景**：玩家进入「沉没的太阳神殿」遗迹，搜查祭坛获得护符。要求：① 遗迹背景故事与物品有关系；② 物品提供特殊能力。

### 推演

**发现（探索态）**：场景携带标签（祭坛/瓦砾/暗格）→ 场景可供性解锁「搜查祭坛」动作（§4.3）→ 结算：种子 RNG 发现判定 → 命中该遗迹的物品池（规则库：遗迹 × 物品池 × 权重）→ 实例化。与 Case 1 的差异：`provenance.source` 是地点而非生物，且新增 `loreRef`。

```json
{ "uid": "item.inst.000318", "template": "relic.sun_amulet",
  "rarity": "epic", "basePrice": 900,
  "loreRef": "lore.sun_cult",
  "abilities": [
    { "slot": "passive", "primitive": "light_resist", "rank": 2 },
    { "slot": "active",  "primitive": "holy_burst",   "rank": 1, "cooldown": 3 },
    { "slot": "cost",    "primitive": "dark_penalty", "rank": 1 } ],
  "provenance": { "source": "location.sunken_temple", "turn": 47, "discoveryRoll": "seed:c7d2" } }
```

**背景故事与物品的关系（loreRef 双向引用）**：
- 正向：物品描述投影包含按 `loreRef` 检索的遗迹背景摘要；Narrator/检索工具（history-recall 模式）需要时拉取完整 lore。
- 反向：玩家携带该护符进入太阳教遗民聚居地 → 触发器条件 `player_owns(loreRef: "lore.sun_cult")` → 激活特殊对话与事件。
- 一致性由内容管线保证：物品效果原语与 loreRef 指向条目的主题标签（神殿带 `light` 标签 → 光系原语）应关联；内容校验器对不关联的草案告警，人工裁决。

**特殊能力**：能力槽（passive/active/cost）引用的仍是原语目录内的效果原语（P4）。遗迹物品的「特殊」体现在三点：更高 rank、独占原语（仅出现在遗迹物品池）、带代价原语（诅咒式权衡）——全部由引擎定价定强度。

**叙事**：发现时刻由 Narrator 从结构化事实（物品、来源、能力、lore 摘要）渲染；Director 可在关键剧情物品被拾取时安排演出拍。

### 验证矩阵

| 要求 | 机制 | 拔掉 LLM |
|---|---|---|
| 遗迹背景与物品的关系 | loreRef 双向引用 + 检索工具 + 内容校验器 | 模板描述含来源与 lore 摘要行 |
| 物品特殊能力 | 能力槽引用原语目录 + 引擎定价 | 完整工作 |

### 暴露缺口

G7（loreRef 引用机制与内容校验 → 已收编 §5.1/§5.4/§14-7）、G8（装备/技能类实体结构：能力槽、词缀、代价原语 → §5.1）。

## Case 3：城镇交易/拍卖

**场景**：玩家在山地城铁匠铺，想卖掉骨杖、买一把区域特供的矮人战锤（有等级限制）。要求：① 互换物品与金钱；② NPC 有经济能力；③ NPC 物品有地域特征与等级限制。

### 推演

**商业态菜单**：买入（库存表条目）、卖出（背包条目）、以物易物、拍卖（该城有拍卖行且声望达标时出现——与 Case 5 联动）。

**互换物品与金钱（原子双向转移）**：卖出 = 定价引擎报价（§8.1，同 Case 1 T2）→ 玩家接受 → 单事务双向账本转移：

```text
player: item.bone.staff -1, gold +300    smith: item.bone.staff +1, gold -300
```

以物易物：双方物品各过定价函数，差价金钱补齐。任何一侧校验失败（背包满、purse 不足）整个交易回滚——回合事务原子性（§12.1 步骤 6）直接复用。

**NPC 经济能力（purse 模型）**：铁匠 `purse: 800`，收购骨杖后剩 500；purse 每游戏日按进货额度刷新（拟态层起步：NPC 钱包是「有上限、会恢复」的状态，不是真实循环；状态化为进阶选项）。purse 不足时收购菜单条目置灰并显示原因。

**地域特征与等级限制（条件可见性）**：商人库存表条目携带条件：

```json
{ "shop": "smith.mountain_city",
  "stock": [ { "template": "weapon.dwarf_hammer",
               "region": "mountain",            // 地域特征：仅山地城铁匠进货
               "requires": { "playerLevel": ">=8" } } ] }
```

菜单生成器（§4.2 基础层）逐条评估条件：等级不够 → 条目置灰/隐藏 + 条件提示；region 由店铺所在地区决定进货表。**买不了的动作在菜单上就不存在或明确锁定**——P3「菜单即边界」的又一体现。

**谈判（LLM 的位置）**：L2 铁匠可讨价还价，报价区间 `[定价×0.8, 定价×1.2]` 由引擎给出，超区间提交被校验拒绝；L0 商人按价目表 + 画像修正。LLM 渲染交易演出。

### 验证矩阵

| 要求 | 机制 | 拔掉 LLM |
|---|---|---|
| 互换物品/金钱 | 双向账本转移，原子事务 | 完整工作 |
| NPC 经济能力 | purse 字段 + 刷新模型 | 完整工作 |
| 地域特征 | 库存 region 标签 + 地区进货表 | 完整工作 |
| 等级限制 | 库存条目条件可见性 | 完整工作 |

### 暴露缺口

G9（商人库存系统：region 标签、进货表、刷新 → 已收编 §8.2）、G10（NPC purse 模型：拟态/状态化分级 → §8.2）、G14（条件可见性统一机制——等级限制首次出现 → §4.4/§7）。

## Case 4：大量杂物出售

**场景**：玩家清完三个地牢，背包 200 件杂物（破剑×80、兽皮×60、矿石×40、杂项×20），回城全部卖给杂货商。要求：① 物品分级记录能力；② 世界经济流转。

### 推演

**性能与分级记录（账本侧）**：杂物全部为模板堆叠（无 uid——具名实例是 Case 1 的例外而非常态）。200「件」实际是 4 个堆叠条目 × qty；卖出 = **一次批量 ledger delta**：四行 remove + 一行 gold add，单事务毫秒级。分级：rarity 分档定价（白 1×、绿 2×、蓝 4×…），itemLog 审计尾日志记录批量交易摘要（story-ledger 的 8 条尾日志模式扩展为可配置长度/汇总式）。

**世界经济流转（市场状态账本）**：核心机制是把「市场状态」做成账本条目（物品类别 × 区域的供需指数），所有买卖都更新它，定价函数读取它（Case 1 T2 定价函数的 market 输入在此做实）：

```text
卖出 80 破剑 → 金属类供给 +80 → 山地区域金属供需指数下移
→ 后续金属类收购价的市场因子下降 → 倾销压价成为涌现行为，且完全确定性
```

三条配套：
- 杂货商 purse 扣减；收走的杂物进商人库存（可被其他 NPC/玩家买走），刷新周期后按销货率清除。
- 世界事件驱动市场漂移：战争爆发 → 触发器 → 铁价 ×1.5（触发器引擎的定时/事件条件）。
- 防通胀阀门：市场因子本身就是阀门——刷卖收益边际递减，无需封顶数字。

**LLM 的位置：无。** 此 case 全程纯引擎，恰好是 P1 的正面压力测试。

### 验证矩阵

| 要求 | 机制 | 拔掉 LLM |
|---|---|---|
| 物品分级记录 | rarity 分档 + 模板堆叠 + 批量事务 + 审计尾日志 | 完整（本 case LLM 本无位置） |
| 世界经济流转 | 市场状态账本（供需指数、漂移、事件响应）+ purse + 销货率 | 完整 |

### 暴露缺口

G11（市场状态账本：供需指数、漂移规则、事件响应、防通胀阀门 → 已收编 §8.3）、G12（批量交易事务形态 → §8.4）。

## Case 5：完成势力委托

**场景**：玩家完成「灰狼佣兵团」委托（清剿盗匪），声望达到「信任」，解锁势力拍卖行入场权与雇佣兵服务。要求：① 获得声望；② NPC 好感；③ 声望解锁势力特殊权益（拍卖、雇佣兵）。

### 推演

**声望入账（原子、硬约束、可审计）**：委托终态阶段 commit（任务阶段机，两阶段提交）→ 触发器级联 → 账本条目原子 delta：

```text
factions.grey_wolves.rep: 18 → 33   (delta +15, 来源: quest.q42, 上下限 [-100, 100])
```

**NPC 好感（两级模型）**：个体好感（per-NPC 条目，互动修正）与势力声望（per-faction）分离又联动——同势力 NPC 的基础好感 = f(势力声望)，个体互动独立修正。团长对玩家的好感 = 基础(声望映射) + 个体修正（历次对话、赠礼）。

**声望解锁权益（条件可见性，与 Case 3 等级限制同一机制）**：

```text
faction_rep(grey_wolves) >= 30 → 城镇菜单中「进入佣兵团拍卖行」「雇佣佣兵」条目可见
雇佣列表再分档：rep>=30 可雇普通兵，rep>=60 可雇精锐
```

菜单生成器评估条件表达式决定条目可见性/置灰。声望不足时权益不存在于菜单（或显示为锁定 + 达成条件提示）。

**叙事反馈（数值与演出分离）**：Director 在声望跨过里程碑（30）时安排演出拍（团长接见、`act_respect` 舞台指令、TTL）；L2 团长 POV 注入声望事实 → 对话态度变化；好感数值驱动 L0 NPC 效用函数中的态度参数。反面：声望为负 → 条件表达式触发敌对（卫兵攻击、该势力店铺物价上浮——联动 Case 4 市场因子）。

### 验证矩阵

| 要求 | 机制 | 拔掉 LLM |
|---|---|---|
| 获得声望 | 声望账本（原子 delta、上下限硬约束、来源审计） | 完整工作 |
| NPC 好感 | 两级好感模型（faction + 个体，联动映射） | 完整工作 |
| 声望解锁权益 | 条件可见性（菜单条目门控）+ 分档权益 | 完整（演出消失，解锁照常） |

### 暴露缺口

G13（声望/好感两级账本 → 已收编 §9）、G14（条件可见性统一机制——再次出现，确认其为跨 case 通用机制 → §4.4/§7）。

## Case 6：主线剧情演变——二皇子叛乱成功

**场景**：世界存在一条主线故事线「二皇子叛乱」。玩家游玩过程中，叛乱走向成功终态。要求：① 叛乱成功自动传导到**所有势力好感度**；② **地域归属**（首府控制权）自动变更；③ 剧情相关 NPC 与物品随之贴合；④ 系统能在游玩中「出现」新的可能主线，并由 Director / ContentGen 指导后续演变。

### 推演

**T0 主线弧的存在与激活（内容期 → 运行期）**：主线不是运行期凭空产生，而是内容期的**故事弧（arc）资产**——入口条件 + 分支结构 + 参数槽，与任务图对齐。运行期当世界状态满足入口条件（§7 条件表达式，如 `faction_rep(royal_house) < -20`）时被确定性激活。

- 缺口：当前设计**没有「主线故事池 / 叙事大纲」资产类型**（§13-7 只列掉落表/物品池/配方/库存表/任务图/lore）；任务图是静态的，Director 只能在图内选阶段（Case 1 T4、§3 L1）。「一条主线」无落点 → **G17**。

**T1 叛乱成功入账（步骤 5→6）**：`quest_stage(rebellion) == succeeded` 经任务阶段机 commit（两阶段提交，同 Case 5）→ 触发器级联 → **声望批量 delta**：

```text
factions.prince_camp.rep: +40    factions.royal_house.rep: -50    （各势力按内容表）
  → 原子 delta、上下限 [-100,100]、来源审计（§9）
  → 同势力 NPC 基础好感 = f(势力声望) 自动重算（§9 两级模型）
```

好感度自动变更**设计内成立**：引擎传导、内容表定义映射（§9 + §7）。

**T2 地域归属变更**：首府易主，`region.capital.controller: royal_house → prince_camp`，并向下传导市场因子、库存进货表、卫兵阵营、可接任务、门控谓词。

- 缺口：设计里「区域」只是市场指数维度（§8.3）与库存进货表标签（§8.2），**没有「区域控制权」实体** → **G15**；连带 NPC 阵营归属变更（如队长倒戈）也无落点 → **G16**。

**T3 NPC 与物品贴合**：NPC 靠 faction/role 标签被舞台指令 target 查询命中、靠 POV 注入获得剧情事实（§3/§9）；物品靠 loreRef + essence + provenance 内容期焊接（§5.1/§5.3/§5.4）。

- 边界：运行期**只传导、不归类**——不会因为「有个叛乱故事」就给已有 NPC/物品补标签或 loreRef。贴合上限 = 内容期标签覆盖率。

**T4 下一弧激活与演变指导**：ContentGen 内容期产弧池并扩池；Director 运行期在池内选弧/推进阶段 + 舞台指令 + POV 注入。

- 缺口：Director **无运行期选弧/推进弧的提议通道**（现有通道只允许图内阶段提议）→ **G18**。
- 注意：改朝换代是大范围级联，须落在 §12.1「触发器级联深度上限」与大事件级联预算内 → **G19**。

## Case 7：拔掉 LLM 的完整体验（离线模式）

**场景**：LLM 全部宕机，玩家继续游玩：与商人对话、战斗、听 NPC 说话、推进主线。要求：① NPC 能行动也能说话（不哑巴）；② L2 NPC 有行为兜底；③ 对话不是空壳；④ 主线仍推进。本 case 即 P5 的正面验收。

### 推演

**T0 NPC 不哑巴（G20）**：L0 效用 AI 决策照常（毫秒级，纯代码）；台词渲染走降级路径——按 intent verb + NPC 画像从模板文案库（§14-7，intent 索引的内容资产）选模板并填充参数：效用 AI 决定「求饶」→ 命中 `template.speech.plead × 语气参数` → 填充出台词。结构性保证：内容校验器要求模板库覆盖全部基础 intent verb，缺 verb 即告警（§14-7 规则③）。

**T1 L2 行为兜底（G21）**：内容校验硬规则保证每个 L2 必有完整 L0 profile（驱力、效用函数、行为树、画像，§3/§14-7 规则②）——宕机的 L2 商人立即落回效用 AI + 价目表 + 模板文案，行为与语言连续，不出现「只写了 L2 提示词、离线无兜底」的 NPC。

**T3 主线推进**：auto 模式弧按 entry 条件确定性实例化与推进（§10）；director 模式弧暂停等待；确定性任务、触发器、经济照常（§12.3）。
