确定性内核 src/kernel/

TypeScript strict · 无 LLM · 无网络 · 无时钟 · 同输入同输出（P7）
turn/ 回合管线§12.1 八步：感知→菜单→决策→校验排序→结算→原子提交→渲染→导演
timeline/ 权威状态唯一写通道 · revision++ · 事件溯源 fold(log) ≡ snapshot
expr/ 条件语言手写递归下降解析 → 可序列化 AST · 触发器/门控/弧共用（§7）
menu/ 菜单 + 三态门控基础层 = 行动空间边界（P3）· 条件可见性（§4.4）
rules/ 规则注册表原语目录 / 定价函数 / 配方 / 遭遇表 · 规则即数据 + 版本（P4）
trigger/ 触发器引擎级联深度预算 · 延迟结算队列 · 大事件传导（G19）
ai/ NPC 三层L0 效用 AI + 行为树 · L1 舞台指令解释器 · L2 会话由外设供给
economy/ 经济定价纯函数 · purse 拟态 · 市场账本 · 批量 delta（§8）
ledger/ 账本物品（实例身份/堆叠）· 声望好感 · 区域控制 · membership（§9/§11）
quest/ 任务 + 故事弧两阶段 prepare→commit · 弧池 select/advance/abort（§10）
entity/ 实体系统能力槽 · essence 继承 · 血统链 · 组合校验 + 定价（§5）
rng/ PCG32状态可序列化 · world/combat/loot 分流 · 掷骰入日志（§14-1）
ESLint 边界强制：kernel/ 禁 import fs / net / crypto / Math.random 效果原语 = (state, intent, rng) → events[] 纯函数 回合号 = 时钟（延迟结算到期队列是状态）

LLM 外设 src/llm/

Provider 接口 · 可拔（P5）· M0 全 Mock / 无
前台体验 Agent正文渲染（为 L0 代笔）+ 菜单增富（参数化变体，过 schema/白名单/去重校验）
Actor Agent（L2）受限 POV · 行动菜单内选 intent · 超时/失败自动落回 L0（G21：L2 必带完整 L0 profile）
Director Agent舞台指令（闭集词汇）+ 任务阶段提议（图内）+ 弧操作提议（池内），全走校验带回执
ContentGen（离线）资产草案 → schema + 一致性校验 → 人工审校入库
适配器：OpenAI 兼容 HTTP / DSH 宿主（待决 5）/ Mock 回放 deadline · SLO 表 · 降级阶梯 = 配置数据（§14-4 / §12.3） 注入防御：消毒管道 + 定界符 + 注入审计（§6，玩家文本永远只是数据）
P1 代码规则主导 — 判定权、数值权、状态变更权全在内核；LLM 是外设不是内核
P5 LLM 可拔 — 拔掉全部 LLM：状态机 NPC + 模板文案，游戏完整可玩
P7 确定性重放 — 种子 RNG + 事件日志，同输入同输出；重放等价测试每次提交跑
P8 Agent 不互通 — 一切通信经引擎中转、结构化、带 revision 门控

存储层 src/storage/

纯本地文件 · 零外部数据库 · 事件溯源 + 内容寻址 · 规则库版本化

① 规则库 content/ 只读 · 随引擎版本走 · git 审校

content/ ├─ primitives.json 效果原语目录（收录范围 = 能力边界 §5.2） ├─ recipes.json essence → 效果原语映射（§5.3） ├─ loot.json 掉落表 ├─ encounters.json 遭遇表 ├─ arcs/ 故事弧池（§10） ├─ topics/ 话题树（§4.2） ├─ templates/ 模板文案库（按 intent 索引 G20） └─ VERSION.json 各域版本号 → 迁移路径（§14-2）
运行时只读不写（P4）；内容管线的 diff / 人工审校（§14-7）= PR review

② 存档 saves/<slot>/ 读写 · 每槽独立

saves/<slot>/ ├─ manifest.json 种子 · 规则版本集 · protoVer · revision ├─ events.jsonl 事件日志（掷骰 + 到期回合）· 追加 only ├─ blocks/ 内容寻址增量状态块（sha256 → JSON） ├─ checkpoints/ 周期快照 + 事件后缀 └─ archive/ 叙事归档 / 舞台指令账本 · 追加 only
唯一写者 = 引擎（经 timeline 事务）；无第二写入者 → 无文件并发问题（P2）
读 · 启动 content/ → 只读 RuleRegistry
saves/ → fold(events + blocks) → 权威状态（内存）
写 · 每回合 timeline 事务（原子 · revision++）
① events.jsonl 追加 ② blocks/ 追加 ③ 周期 checkpoints/
校验 · 存档 / 重放 checkpoint + 事件后缀重放
fold(log) ≡ snapshot（启动与测试时校验，P7）
写通道唯一（P2） 追加 only：events / blocks / archive 内容寻址：几百回合不膨胀（§13） 规则版本 + 确定性迁移注册表（§14-2） JSONL 文本 diff 友好
为什么不引 SQLite —— 数据形态是「追加日志 + 重放派生态」：每回合状态在内存、账本索引是 Map，关系查询与事务能力用不上，反而引入原生依赖与打包负担。跨存档的平衡性分析走 src/sim/ 离线批跑，不需要在线库（§11）。
依赖方向（ESLint 强制）：kernel ← storage / llm / api；api ← server / cli / sim（api 是唯一组装点）。 工具链：TypeScript strict · Node 22 LTS · pnpm · vitest · tsup · Node SEA 单文件分发。 演进：M0（内核切片，CLI）→ M1（LLM 外设 + Web 台）→ M2/M3（Director + 经济全量 + 即时制）→ M4 + Godot G2（游戏化 + 打包）。
